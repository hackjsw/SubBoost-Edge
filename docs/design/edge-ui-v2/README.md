## 设计原则

- 主线是“导入节点 → 选规则 → 保存得到订阅链接 → 客户端使用 → 自动更新与排障”，界面围绕这条线组织。
- 与上游 SubBoost 的共享界面分开：Edge 专用页面在 `edge/` 下独立实现，不再受上游多用户、配额等概念约束。
- 深色主题为“石墨灰”（2026-10-02 由原“科技”配色改定）：中性深灰底色 `#111316`、卡片 `#181b1f`，强调色为橙色（深色 `#fb923c` / 主按钮 `#f97316`，浅色 `#ea580c`），警告改用黄色以免与强调色混淆；不使用网格背景、光晕和渐变。失败用红色。
- 数字、链接、延迟等数据统一用等宽字体；下拉框的选项列表也使用主题色，避免深色模式下弹出白色列表。
- 原浅色主题保留为对照（`?light`），所有颜色都通过 CSS 变量定义，便于实现时切换主题。
- 正文不小于 14px、辅助文字不小于 12–13px，文字与背景对比度满足 WCAG AA；按钮可用/不可用状态明确区分。
- 纯图标按钮一律带文字或提示；手机上点击区域不小于 40px。

## 页面要点

### 生成器

1. 页面标题改为“新建订阅”（编辑时为“编辑订阅”并显示退出编辑确认），去掉重复的品牌大标题。
2. 三步结构：订阅来源 → 规则方案 → 保存。采用“结算页式”布局：左侧为加宽的主操作区，只放前两步；右侧为约 350px 的窄栏，“③ 保存”与预览概览合并为一张卡片并随页面固定（sticky），无论左侧展开多少内容，都不必滚到底就能保存，左右视觉重量也更均衡。
3. 来源列表末尾始终保留一个“添加来源”空白框（虚线、强调色标题），不需要点“添加”按钮：
   - 粘贴后该框变成已识别的来源卡片（订阅链接 / YAML / 节点链接），并自动在下方留出新的空白框；
   - 一次粘贴多行时，多个订阅链接拆成多张卡片，多条节点链接合并为一张“节点链接 · N 条”卡片；
   - 支持把 `.yaml` 文件拖入空白框；
   - 来源卡片显示解析结果（节点数、流量），订阅 token 默认打码，可拖动排序或移除。
4. 内置规则与 ACL4SSR 模板放在同一步，并标明“本地生成 / 经转换服务生成”。
5. 保存卡片：订阅名称（默认取自第一个订阅来源）、自动更新（默认每 24 小时）、主按钮“保存并获取订阅链接”，下载 Clash / v2rayN 作为次要按钮放在其下方；不改任何设置也能直接保存。
6. 保存卡片顶部是预览概览（节点数、代理组、规则数、地区分布标签、去重等提示）；“查看 YAML”“关系图”点击后从右侧抽屉打开，不再常驻占用版面。
8. 手机上：预览收成一条摘要；底部固定栏显示“名称 · 自动更新频率 · 修改”和保存按钮，点“修改”在底部面板里改名称和频率。
7. 取消“快捷 / 高级”两套界面，合并为同一个三步结构：第 2 步先选模板，再通过“自定义”开关展开原高级模式的内容（见下节）。

### 订阅来源的识别与失败处理（`source-states.html`）

1. URL 一律先当作订阅链接拉取，拉取后按内容判断格式（Clash YAML / Base64 / 节点链接），卡片显示识别结果；每张卡片右上角都有类型选择，可随时从“自动识别”改为指定类型。
2. 粘贴的文本判断不了时，卡片变黄并给出推荐类型（例如看起来像 Base64 时推荐“Base64 节点列表”）。
3. 纯 IP 地址的订阅（如 `https://1.2.3.4:2096/...`）：Cloudflare Workers 不能直接请求 IP 地址（会返回 403），粘贴时就提示，并提供“改为粘贴订阅内容”（不能自动更新）和“给服务器绑定域名”的说明。
4. 服务器拒绝（401/403）：说明已尝试的客户端标识，可指定其他标识（mihomo、Clash Verge、v2rayN、Shadowrocket、自定义）重试，或改为粘贴内容。
5. 拉取成功但没有节点：提示可能是订阅到期或返回了说明页面，可查看返回内容。

### 预览抽屉（关系图 / YAML）

从保存卡片的“查看 YAML”“关系图”打开，右侧滑出约 780px 的抽屉（手机上全屏），两个视图用顶部切换。

1. 关系图：三栏流向图“规则 → 代理组 → 出口”。出口按地区汇总节点，另有 DIRECT、REJECT。点选一个代理组，高亮它的规则来源和可选出口，其余变淡；底部详情显示类型、默认出口、规则数量和可选出口说明。手机上隐藏规则栏，规则信息放在详情里。
2. 关系图只读，调整分组和规则仍在“自定义”中进行；代理组顺序可直接拖动调整（沿用现有能力）。
3. YAML：分段跳转（基础与 DNS、proxies、proxy-groups、rule-providers、rules，带数量）、搜索高亮与命中数、语法高亮和行号。
4. 默认隐藏密码、UUID 等敏感信息，可开关；复制和下载得到的始终是完整配置。

### 自定义（原高级模式）

1. 订阅来源和保存两步与默认流程完全相同；差别只在第 2 步。
2. 打开“自定义”后，在所选模板基础上调整（与现有逻辑一致：选择模板会设置启用的分流代理组，并清空自定义规则），提示“切换模板会重置分流代理组和自定义规则”。
3. 五个折叠区：节点管理、中转代理组、分流代理组、规则、DNS 与基础设置。折叠时显示一行摘要，改动过的区块带“已修改”标记。
4. 节点管理：搜索（支持正则）、测试连通性、批量改名、监听端口；每个节点显示协议、延迟（颜色区分）、改名与排除，排除的节点可恢复；默认显示前几个，可展开全部。
5. 分流代理组：勾选卡片 + 自定义分组；默认显示常用分组，可切到全部。
6. 选择 ACL4SSR 模板时，分流代理组和规则由远程模板决定，这两项自定义停用。
7. 内容随页面整体滚动，不再在固定高度的卡片里滚动。

### 我的订阅

1. 配额卡片换成状态：订阅数、自动更新正常、更新失败（可点击筛选）、下次定时更新时间。
2. 规则库状态压缩为页面底部的一行。
3. 列表增加筛选：全部 / 更新失败 / 自动更新 / 手动，以及搜索。
4. 每行：状态点、名称、规则方案和更新频率标签、相对时间、节点数、流量与到期；更新失败直接显示原因和“立即重试”。
5. 操作收敛为“复制链接”（右侧下拉选格式）、二维码、更多（编辑、设置、刷新、下载、删除）；手机上“更多”改为底部弹出面板。
6. 手机底部导航：生成器 / 新建 / 我的订阅（源码下载移到页脚）。

### 复制链接 / 二维码

1. Clash / Mihomo 与 v2rayN 两种格式切换。
2. 二维码便于手机客户端扫码导入（设计稿中的二维码为示意图案）。
3. 不提供“一键导入到客户端”，客户端通过复制链接或扫描二维码导入。
4. 桌面为居中弹窗，手机为底部弹出面板。

## 已确认的决定（2026-10-01）

1. 整体方向确认；深色主题采用“石墨灰”配色，同时提供浅色主题，默认跟随系统。
2. 订阅列表显示节点数、流量与到期信息。
3. 不做“一键导入到客户端”。
4. 二维码用零依赖的轻量库 `uqr`（直接输出 SVG），只在打开二维码弹窗时按需加载，在浏览器本地生成，不经过 Worker。

## 实现时需要补充的数据或依赖

- 订阅列表接口需要返回节点数、流量与到期信息（记录中已有 `subscriptionInfo` 和节点列表）。
- “转换结果 xx 分钟前缓存”需要接口返回 ACL4SSR 转换缓存时间，可在实现时决定是否保留。
- 二维码：按需加载 `uqr`。
